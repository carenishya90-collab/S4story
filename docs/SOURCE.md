## Как собрана эта версия

Это **не полная сборка из исходников**. Русская версия собрана так:

1. Взят официальный бинарный релиз `v5-beta.15.1`.
2. Заменены три DLL с русскими ресурсами:
   - `Constructor5.Base.dll`
   - `Constructor5.UI.dll`
   - `Constructor5.Elements.dll`
3. Заменены 1275 файлов `Presets/**/*.Presets.xml` с переведёнными названиями.
4. Удалены служебные файлы, которые не должны попадать в релиз.
5. Добавлены README, NOTICE, BUILD_INFO и контрольные суммы.

Структура XML в пресетах не менялась: проверено, что число элементов и атрибутов совпадает с оригиналом. Перевод затрагивает текстовые значения.

## Что именно изменено

Точный список с SHA256 лежит в `manifest/localization-manifest.json`.

Кратко:

- 3 DLL;
- 1275 XML-файлов пресетов;
- текстовые файлы релиза.

Остальные файлы официального релиза не изменялись.

## Русский XML-ресурс

В `Constructor5.Base.dll` находится ресурс:

```text
Constructor5.Base.LocalizationSystem.LocalizableTextStringsXML.xml
```

В русской версии:

- 1260 строк;
- все 1159 ключей оригинала;
- 101 дополнительный ключ для новых экранов;
- 1155 переведённых строк;
- 4 строки совпадают с оригиналом (например, технические обозначения).

## Ограничения воспроизводимости

Полная сборка из исходников пока невозможна без восстановления UI-изменений:

- в `Constructor5.UI.dll` есть три дополнительных BAML-экрана (`ArchiveWindow`, `CareerDetailedHelpWindow`, `ElementCreationHelpWindow`);
- BAML переведён и изменён, но исходные XAML-файлы этих изменений в репозитории не восстановлены;
- для чистой source-сборки потребуется Visual Studio 2022, .NET Framework 4.8 и пакеты NuGet, а также восстановление BAML/XAML.

Поэтому текущий релиз следует считать **бинарной локализацией официального релиза**, а не независимой source-сборкой. Это ограничение нужно явно указывать в описании GitHub.

## Следующие шаги для полной source-сборки

1. Восстановить XAML дополнительных окон из BAML или найти исходные файлы.
2. Добавить русский `LocalizableTextStringsXML.xml` в `Constructor5.Base`.
3. Перенести переводы пресетов в исходные `Presets`.
4. Собрать решение в Visual Studio 2022.
5. Сравнить поведение с текущим бинарным релизом.
6. Перейти на source-сборку в следующей ревизии.

Эти шаги не блокируют текущую публикацию, если в README честно указано происхождение сборки.
